# Appliances

Read `device_read` first: appliances refuse commands for reasons the state shows (remote control off, door open, child lock, a running cycle), and the refusal names the reason, which you report as given. `device_control` sets one capability per call: send the settings first, check each result, and send a start only after they succeeded.

## Washer-dryer

Read `device_read` first. The machine's remote control must be on (`remote_control` true) or Start fails; report that reason. Send power (if off), the program and then each option it uses, one `device_control` call each, and check every result succeeded; only then send `cycle_start`. Changing the program resets its options, so send every option you want. For finish-by set `delay_mode` Finish Wash and `delay_minutes`. Options are locked during a cycle. Use `door_release` only when paused with the door line saying it is safe. Never start Drum Clean with laundry inside. `cycle_stop` needs your confirmation unless the person said stop. Report `remaining_minutes` and the finish time from it.

## Microwave

Read `device_read` first. Every cooking write needs Remote control on, the door closed and the child lock off; a refusal names which, so report it. Set the Cooking mode in its own `device_control` call, then in the next send the Set cooking duration (an object with `operationTime` as hours:minutes:seconds), Microwave power and Cooking temperature that mode accepts (the capability lists the allowed values; an option the mode lacks is refused with the reason), and only then Start cooking. Some modes can be set but only started on the appliance: say Press Start on the microwave. Pause cooking and Stop cooking need only remote control. Read the Operating state, progress and finish time from `device_read`, and past cooking cycles from the `readDeviceLog` operation.

## Printers

A network printer (IPP, AirPrint-compatible) is a device of family `printer` (`device_find` with that family). `device_read` gives its state (`printer_state`: idle, printing, stopped), the queue (`queue`: running or paused), the number of waiting jobs, the problem keyword if it has one, the pages printed today, the lowest supply and the days left, and each supply, tray and output bin as readings. Supplies are cartridges, toner and a waste tank; a level the printer does not report is unknown, never zero. The waste tank is a supply that fills up: it is low when it is nearly full.

- Printing, the queue, history and statistics use the printer plugin's `printer` (read) and `printer_action` tools; find them with `tool_search`. Read views: overview, supplies, trays, queue, jobs, stats, options (what this printer can do and the print settings it accepts), candidates, settings (owner only). Omit `printer` when only one is set up.
- `printer_action` takes an `action`: print (a PDF, JPEG, PNG or WebP from an upload, an attachment or a computer file; ask for copies, sides, colour, quality or paper only when the person said so, and read the options view first so you never send a setting the printer does not list), test_page, cancel, hold and release (a job key), pause and resume the queue, identify (beep or flash so the person can find it), the printer's own web page link, and configure for the caller's own print defaults. Adding a printer, rescanning, forgetting it, cancelling every job, trusting a new certificate, entering its sign-in and clearing its history are owner only; an encrypted printer with a self-signed certificate asks the owner to confirm its fingerprint first. Never ask for or repeat a printer password in chat.
- A member sees and cancels only their own jobs; other people's document names are hidden and the owner sees everyone's. Print only what the person asked for and say what you sent (name, copies, sides). A paused or stopped printer, an empty tray or a jam is reported as given with the plain cause from the problem keyword; do not retry a refused print.
- Ink and toner: `history_read` reads `printer` supply levels over time, the supplies view gives burn rate, days left and a forecast of when it runs out, and a cartridge replacement is a mark on that history. Say when a forecast is rough because there is little history.
- The printer sends plugin events (`job_started`, `job_finished` with the result, `problem_added` and `problem_cleared`, `supply_low`, `supply_empty`, `supply_replaced`, `restarted`, `offline_long`); see `smarteverything-automations`.

## TVs

Read `device_read` first; its `television` part gives the direct link (`direct_link`: the screen's `address` and the `mac` that wakes it, or null when not linked) and the names given to inputs (`inputNames`, input id to name; the TV's own input ids come from the `input_source` options). A linked screen is controlled over the home network first (power, keys including numbers and colours, apps) with SmartThings only as the backup, and it is turned on with Wake-on-LAN to the MAC the link read from the screen itself. A sleeping TV reads off, not broken; `power` on works only when the device has a wake path (the direct link, remote power on while SmartThings sees it, Wake-on-LAN when `wakeAddress` is set, or an IR remote), otherwise say how to fix it. To link a screen, the person opens that screen's settings in the app while it is on, chooses Link directly, picks the screen and chooses Allow on the screen with its remote; the AI cannot approve that prompt. The `listTelevisionCandidates` operation (`operation_call`; `tool_read` gives its input) lists the Samsung screens on the network with their address, MAC and the device each is already linked to. The `findTelevision` operation looks once for a screen that is not linked directly, saves its address when it is certain which screen it is and starts the link so the screen shows its Allow prompt; it does nothing for a linked screen, and the person still chooses Allow on the screen. An offline screen with a `wakeAddress` and no direct link is woken over the home network and the command succeeds only once it comes online; when it does not, tell the person to turn on Power On with Mobile on the screen (`last_wake_worked_at` says when a wake last worked). Without a direct link or a `wakeAddress`, suggest linking it directly; only if the person prefers, set the screen's network MAC address (on the TV: Settings, General, Network, Network Status, IP Settings, or About) with `device_edit` (`wakeAddress`, null clears it); never guess it from another screen. Open an app with one `app_launch`, not key sequences. Navigate with `remote_key` names such as `up`, `ok`, `back`, `home`, `vol_up`, `mute`, `n0` to `n9`, `red`, `green`, `yellow`, `blue`; a key the TV's paths cannot send fails with a reason, so report it. Picture and sound modes are the options `device_read` lists. IR presses are unconfirmed.

Use `widget_show` for a live device, remote or weather card. A widget a plugin adds is a board type like any other (`pluginId.widgetId`, listed by `plugin_read`): `widget_show` kind `board` shows it and the board layout operations place it on the Home board.

## Air, sensors and the desk robot

- Air purifier: Purifier mode (role `purifier_mode`), Favourite level and fan mode are the controls; humidifier: `target_humidity`, `mode` and `mist_level`. Child lock is a setting. Filter life and days left are readings; call `filter_reset` only when the person says the filter was replaced.
- Contact, motion, leak and smoke sensors only report: read them with `device_read`, find when they changed with `history_read` or `event_find` (opened, leak, smoke), and react to them with an automation, never with a command.
- AIBI, the small desk robot, is a device with one control, Move or act: send an object with `action` and `options` through `device_control`. It moves only while AIBI is in a conversation (the move rides with its next answer) and is refused with that reason otherwise, so `voice_speak` to it or ask the person to talk to it first. Its plugin tools (`plugin_read`, `tool_search`) read its status, what it heard and did, and the moves it offers with their options (read them before choosing a move), and can make it forget its conversations, which only the person's request justifies.
