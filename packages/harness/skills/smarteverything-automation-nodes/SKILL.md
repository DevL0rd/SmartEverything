# Automation nodes

The node catalog is the contract: `automation_read` view catalog lists every kind with its ports, types, picker sources, run modes and plugin origin, and only those kinds and port names exist. Every port holds a literal or a wire; there are no formulas, so every calculation is its own node.

## Nodes and wires only

An automation is a flow chart of nodes joined by wires. Formulas, expressions and text templates do not exist anywhere: a port that needs a worked out value gets a wire from the output of a node that works it out. Build every program this way, step by step:

1. Every port, branch condition, case condition, structured output, variable start value and `admit` holds exactly one of two things: a constant `{"lit": value}` or a wire `{"wire": {"from": "<source>", "port": "<output>"}}`. Nothing else is accepted.
2. A wire's `from` is the `key` of a node that comes earlier (a loop or try gives `item`, `index` or `error` to the steps inside it), or one of five sources: `trigger` (the outputs of the trigger that fired, plus `key` and `at`), `inputs` (the inputs of a Custom Node or called automation), `vars` (a variable, by name), `home` (`timeZone`, `name`, `latitude`, `longitude`) and `run` (`id`, `startedAt`). `port` is one output name. To read a field inside a record, wire the record into Get field (`object.get`) and wire on from its `value`.
3. Work values out with calculation nodes. They never act, and can sit anywhere before the node that reads them: Compare (`logic.compare`: equal, not equal, greater, at least, less, at most), `logic.between`, Is one of (`logic.in`), And and Or (`logic.and`, `logic.or`: two to four flags wired into `a`, `b`, `c`, `d`), Not, Has a value (`logic.exists`), First available (`logic.coalesce`, with a `default`), Choose (`logic.select`: `condition`, then `whenTrue`, else `whenFalse`), Which trigger (`logic.trigger_is`), Add, Subtract, Multiply (two to four values in `a` to `d`), Divide, Remainder, Round, Clamp, Message (`text.format`: a fixed `template` whose `{a}` to `{d}` are filled from the values wired into `a` to `d`), Text check (`text.test`: contains, starts with, ends with, equals, is empty), Join, Count items (`list.length`), Get item (`list.get`: first, last or by index), Any item, Every item, Keep where and Find (`list.any`, `list.all`, `list.filter`, `list.find`: each compares every item, or one `field` of every record, by `test` with `value`), Field of each (`list.field`), Get field, Convert (`util.convert`: to number, text, on/off, duration, moment or list) and Lookup table (`util.lookup`).
4. Decide with wires too: an If branch `when`, a switch case `{"when": ...}`, the wait-for-condition `condition`, `admit` and the `condition` of `trigger.becomes_true` each take a wire to a flag, usually the `result` of a Compare, And, Or, Not or Has a value node. A switch on a value takes the wire in `subject` and fixed cases (`eq`, `in`, `range`).
5. An optional output (optional in the catalog) cannot feed a port that needs a value: test it with Has a value and branch, or pass it through First available with a `default`. A number wire fits any number port; for another type wire it through Convert.
6. Effects (device commands, notifications, tool calls, Value and variable changes) are always their own nodes on the run path, never inside a calculation.

Example: lights to step 1 when the step is 0 or no light is on. “stepIsZero” is a Compare with `a` a wire from `vars` port `step`, `op` eq and `b` 0; “noneOn” is a Compare with `a` a wire from “onNow” port `count` and `b` 0; `either` is an Or with `a` wired from “stepIsZero” port `result` and `b` from “noneOn” port `result`; the `flow.if` branch `when` is a wire from `either` port `result`.

Per-room logic is one Custom Node, never copies. Give it inputs for what differs per room (for example `lights` a target, `event` a choice, `sensors` a list of devices, `allowed` a flag), keep what it must remember in `persist` variables, and build its body from the nodes above. Each room's automation then holds its triggers and one `fn.call` with the room's constants and wires, for example `event` wired from a Lookup table or Choose fed by a wire from `trigger` port `key`. Change the Custom Node once and every room follows.

## Nodes

Common nodes: `device.set` (`target` device, devices, room or group; `control`; `to`; `percent`; `by` adds to a number; `transition` fades where the device can), the temporary-set node of the `device` group (the control returns to its base after a time, when its `while` condition turns false, or when stopped; `priority` orders overlapping changes), `device.get`, `scene.run`, `flow.if`, `flow.switch`, `flow.repeat`, `flow.while`, the for-each loop, `flow.wait`, the wait-for-event and wait-for-condition nodes of the `flow` group, `notify.person` (really pushes), `notify.feed`, `notify.speak`, `var.get`, `var.set` and `var.change` (Values and variables), `automation.run`, `automation.stop` and `fn.call` (a Custom Node). A run keeps going when a scene or automation it uses is edited. Loops have no limit unless one is set: `flow.repeat`, `flow.while`, `flow.do_until` and the loop-until-break node `flow.forever` take an optional `limit` (`iterations`, `time` in ms, `onLimit` fail or end, optional `note`), the for-each loop runs any number of items at once with `concurrency`, and the automation's `budgets` (steps in a row, steps per run, loop passes, run chain length, side-by-side branches) are optional too; only `commandsPerMinute` (600) and the run state size guard (`runStateBytes`, 8 MiB) have defaults. A run never blocks the hub and `automation_stop` ends it at any time. A `flow.forever` needs a Break, Return or Stop inside or a `limit`; the checker names what a loop lacks.

`computer.audio` takes an `action` (`volume`, `mute`, `default`, `app_volume`, `app_mute`, `app_output`) with typed ports: `kind` (output or input), `device`, `app`, `level` and `muted`. `computer.display` takes an `action` (`enable`, `disable`, `mode`, `scale`, `rotation`, `primary`, `position`, `mirror`, `brightness`, `hdr`, `vrr`, `night_light`, `keep`, `revert`) with typed ports: `output` (the screen), `width`, `height`, `refreshHz`, `scale`, `rotation`, `relativeTo` and `side`, `mirrorOf`, `brightness`, `enabled`, `vrr`, `nightLight` and `temperature`. Display settings are always `computer.display`, never `tool.call`. Read `computer_read` first for the exact names and the features the computer offers; a node the computer does not offer, a device that is not a computer, or (for a member) someone else's computer is refused when saved. Nobody is asked while it runs, so a screen change that can blank a screen (`mode`, `scale`, `position`, rotation, main screen, turning a screen off, mirroring) goes back by itself after 15 seconds unless someone keeps it at the computer. Add `keep: true` to keep it automatically once the hub has read the screen back and seen the change applied; if it does not match, the change is reverted at once and the node fails.

The run policy `mode` is single (default), restart, queue or parallel; queue needs `max` (and may take `maxWait`), parallel may take one. `key` names runs so `automation_stop` can end only those. Custom Nodes (`fn.call`) may call themselves or each other: recursion is allowed with no depth limit, and a runaway recursion is stopped by `automation_stop` or fails when its run state grows past `runStateBytes`. An `automation.run` node refuses to start an automation already in its own chain of runs unless it sets `allowSelf`.

`ai.wake` (`person`, optional `chat`, `instruction`) wakes that person's AI with what happened. `tool.call` (`person`, `tool`, `args`) calls an enabled assistant tool without an AI turn, using the exact arguments from `tool_read`. Use it only for a tool no node covers: lights, climate, appliances, cameras, vacuums, TVs, calls, computers, phones, locks, speech, pictures, chats and health all have nodes (next section), and a plugin's own actions are plugin nodes. Both are for the owner.

Every automation records who made it in `author` (`via` person or assistant, and `profile_id`), and a plugin in `origin`; `author` is null only for automations made before this was recorded. Never create, change, switch, run or remove an automation the person did not ask for, and never touch one only because it looks wrong: say what you noticed.

## First-class nodes

Look in the catalog group before anything else: each of these is a node with typed ports and pickers, and `tool.call` never replaces one. A target port takes devices, a room or a group, and all of them are sent to at once.

- Lights: `light.set` (`power`, `brightness` in percent, `color`, `colorTemperature` in kelvin, `effect`, `transition`) sends each light one command with everything in it. A colour is a name, hex such as `#ff8800`, `{"r":255,"g":0,"b":0}` or `{"hue":0,"saturation":100,"value":100}`; a colour and a colour temperature cannot be combined.
- Climate and appliances: `climate.set` (`power`, `mode`, `temperature` with `unit` c or f, `fan`, `fanSpeed`, `swing`, `oscillation`, `offTimer`), `appliance.set` (a writable `setting`, then `value` typed by it) and `device.action` (press an action button). `ir.appliance_set` brings an infrared appliance to a state (`power`, `mode`, `temperature`, `fan`). `laundry.start`, `laundry.control` and `laundry.read` run and read a washer or dryer.
- Security: `lock.set` (owner only), `alarm.set` (a mode the panel offers) and `cover.set` (open, close, stop or a position).
- Cameras: `camera.snapshot` (the picture id), `camera.record` (clip length in seconds), `camera.move` (a saved `preset` or a `direction` with `steps`) and `camera.set` (privacy, motion, `nightVision`, status light, or every camera). Speech on a camera, speaker, computer or phone, or on a Talk channel, is `notify.speak` (`target`, `channel`, `text`, `priority`, `volume`, `voice`), never `tool.call` with `voice_speak`.
- Vacuums: `vacuum.command` (start, pause, resume, stop, dock, spot), `vacuum.station` (dust, mop and tank jobs), `vacuum.clean_rooms` (home `rooms` matched through the room links; unlinked rooms are left out and listed in `unlinkedRooms`, never guessed) and `vacuum.read`.
- TVs: `tv.control` takes an `action` (power, volume, `input`, `channel`, `app`, remote `key`, art mode, `playback`, picture and sound mode).
- Calls: `call.person` (ring one person's `device`: phone, computer app or any; outputs `answered`, `outcome`, `timedOut`, `outreachId`), `call.open` (talk through a camera or a Talk channel) and `call.end`.
- Computers: `computer.audio` and `computer.display` (above), `computer.power` (lock, sleep, hibernate, restart, shut down, sign out, wake), `computer.system` (power mode, do not disturb, keyboard layout, Wi-Fi, Bluetooth, startup apps, services), `computer.app` (open, close, focus, minimise) and `computer.open` (a link or a path). Clicking and typing on a screen stays with the assistant only.
- Phones: `phone.ring`, `phone.sound`, `phone.media`, `phone.open`, `phone.flashlight`, `phone.screen` and `phone.toggle`; `phone.action` is the general one. `notify.person` also takes `image` (a picture id), `priority`, `tag`, `link` and `sound`.
- Pictures and chats: `ai.image` makes a picture and returns a picture id that works wherever a `camera.snapshot` id does (push message, Discord, print); `ai.vision` looks at a picture, a `camera`, or with `source` a computer screen, a computer window or a phone screen. `chat.post` puts a message in a person's chat, `transcript.read` reads what a source heard and `listening.set` changes how a source listens.
- Health and events: `health.today`, `health.range`, `health.read`, the water-logging node of the `health` group and `event.count`. `device.query` finds devices by room, group, family or role.

## Run mode and the If it fails exit

In the catalog `modes` gives a step's default and allowed run mode, and `fallible: true` means it has the If it fails exit. Set a mode, a `timeout` or `onError` in the node's `policy`, or with a patch `set` op (`mode`, `timeout`, each cleared with null).

- `fire_and_forget` (plain commands default to it) continues as soon as the command is handed over; `wait_for_result` (reads, questions and everything else, always) continues when the device confirms or the answer arrives, and fails with `Timeout` when `timeout` passes. Only kinds whose `modes.allowed` lists both accept a mode. A failed send fails the node in either mode; a missing confirmation after a send never fails or reroutes the run.
- Outputs the catalog marks `waitOnly` (for example `ok` and `spokenOn` of `notify.speak`) exist only when the node waits. Wiring one from a node that sends is an error in `automation_edit` check: set that node to `wait_for_result`.
- Wire a step's `onError` exit (connect from the port `onError`, which also sets `policy.onError` to `route`) to the steps that handle a failure. There, wire from the failing node's `key` the ports `reason` (`Refused`, `Unreachable`, `Timeout`, `Invalid`, `NotFound`, `Forbidden`, `Failed`, `LimitExceeded`, `TypeError`, `MathError` or `Unknown`), `message` and optional `code`. An exit nobody wired behaves as `policy.onError` says (`fail`, the default, or `continue`); `BudgetExceeded` and `Cancelled` are never caught. Only fallible kinds have the exit; `flow.try` still does `finally`.

## Typed values

Fill a port with the type the catalog shows: a `choice` takes one of its option ids, a number takes a number inside its `min` and `max` (percent ports 0 to 100), a duration is milliseconds, a `ref` takes an id or a wire. A catalog `pickers` entry names where a port's value comes from (`device.writable_controls`, `climate.modes`, `vacuum.rooms`, `tv.inputs`, `talk.channels`, `voices`, `phone.apps`, `computer.displays`, a plugin's own entities): read the real options with the tool for that area (`device_read`, `computer_read`, `plugin_read`), never invent an id or paste JSON into a text port. A port typed by another (`to` by `control`, `value` by `setting`) takes what that control accepts, in its own unit. Free text is only for text that is itself the content, such as a message or a prompt.

## Plugin nodes

A plugin declares its own nodes, triggers, Values and entity lists, and they are first class. They sit in the catalog group `plugins` with `origin` (kind, id, name) and `available`; an unavailable one carries the reason (plugin switched off, runs as an external local process, owner only). Ids are `plugin.<owner>.<id>` and `trigger.plugin.<owner>.<id>`, where the owner is the plugin id with `-` as `_`, or `driver_<id>` for a local driver. Never use `tool.call` for something a plugin node does; if the node is unavailable, tell the person why instead of falling back to a tool.

## Integration nodes

Read the node catalog (`automation_read` view `catalog`) for exact ports. `ai.ask` runs one model call for a person and returns `text`, `result` (when a `shape` is given), `tokens` and `cost`; it has no tools unless `tools` names them, so give it tools only when none of its inputs come from outside the home. `ai.vision` does the same on pictures or a `camera` (the Bedroom camera stays blocked) and `ai.decide` returns a yes or no `answer` with a `reason`. A member's AI call runs as that member and stops at their budget. `camera.snapshot` stores a picture and returns its id for later `ai.vision` calls. `health.read` and `signal.emit` read the person's health data and act on the signal bus; `http.respond` answers the webhook that started the run, once.

## More nodes

All of these are in the catalog; read it for exact ports. Pure ones only compute and never send anything.

- Devices: `device.snapshot` (Remember state) reads chosen controls of the target at the moment the run reaches it, so a `device.restore` wired straight to it puts back what was there then, however many changes come between; `device.restore` skips offline devices and says which. `device.aggregate` (Across devices) leaves offline devices out of any, all, none, count and the number functions and lists them in its `offline` output. `scene.capture` saves the current values of devices as a scene (`overwrite` must be on to replace one of the same name). `device.fade` moves a number control (brightness by default) from one level to another over a time, paced by the command budget; stopping leaves it at the current level. `device.ensure` sends a value, waits for the device to report it and sends again if it does not, for devices whose cloud drops commands. `device.ir_send` presses a button of a learned infrared remote through its blaster.
- Readings: `computer.read` and `phone.read` return what a computer or phone reports now (a figure it does not report is left out), `signal.latest` reads the newest signal of one kind since the hub started (it never wakes a wait: use the wait-for-event node for that), `weather.forecast` reads the next hours (rain chance, wet hours, lowest and highest temperature, strongest wind) and `date.sun_times` gives sunrise, sunset, twilight, solar noon and golden hour (absent when the sun does not reach that day; fails when no home location is set).
- Flow: `flow.forever` repeats until a Break, Return or Stop. `debug.breakpoint` (Pause here) pauses a dry run or simulation until the person continues.
- Logic: `logic.and`, `logic.or` and `logic.not` combine flags, `logic.changed` tells whether a value differs from the last run of this node in this automation (the first run counts as changed), `logic.count_true` counts true flags against `atLeast` and `atMost`, `logic.xor` is true when exactly one flag is, `logic.day_type` tells weekday, weekend or one of the dates you list (no holiday calendar is built in), `logic.in_schedule` tells whether a moment falls in weekly slots (a slot that ends after midnight belongs to the day it starts on).
- Numbers and chance: `math.convert_unit` converts within one kind of unit (temperature, length, power, energy, pressure, speed, colour temperature, volume), `math.percent` gives a percent of, a percent change or a percent value (a zero base fails), `random.chance` is true with a probability from 0 to 1 and `random.duration` picks a duration between a minimum and a maximum; random results are captured for the run and a simulation can seed them.
- Text: `text.case` trims, changes case or makes a slug, `text.slice` cuts, shortens with an ellipsis and pads, `text.speakable` writes a number, duration or moment the way it is said aloud (numbers and durations are English).
- Lists: `list.range` (numbers from one to another in steps), `list.slice` (a run, the first N or the last N), `list.sort` (numbers or texts, or records by a `field`; mixed kinds fail), `list.unique` (optionally by a `field`), `list.combine` (join, union, intersection or difference) and `list.reshape` (reverse, flatten one level, chunk or zip). To work through a list item by item use the for-each loop with `collect`, or `var.change` inside it to add up.
- Records: `object.fields` takes a record apart into keys, values and entries or builds one from entries, `object.merge` (a later record wins; `deep` merges inside records), `object.pick` keeps or omits listed fields and `object.remove` drops the field at a path (a missing path fails unless ignored).
- Time: `date.next` is the next moment a time of day comes round on chosen weekdays (daylight saving handled) and the start-of node of the `date` group is the first moment or last millisecond of a day, week (Monday), month or year in the home time zone.
- Secrets: `var.secret` hands a stored secret to a node that accepts one, such as the `auth` of `http.request`; its value is never shown, recorded or readable as text. Owner only.
