# SmartEverything kit: sync notes

## Shape and route

- Package shape, no Storybook, no `dist/`. `.design-sync/build-kit.mjs` (the config `buildCmd`) synthesizes a fake package at `.design-sync/.cache/kit-pkg/` (gitignored, regenerated every run): `dist/index.js` (ESM esbuild bundle of every component in `apps/app/src/components`), `dist/index.d.ts` + `dist/types/**` (real `tsc` declaration emit), `dist/styles.css`, `docs/icons-and-colours.md`. `config.entry` points at it. Run `.design-sync/rebuild.sh` for build-kit + converter; `resync.mjs ... --entry .design-sync/.cache/kit-pkg/dist/index.js` for the driver.
- Styling is the app's own: the CSS is the output of `expo export --platform web` (Metro + Uniwind + Tailwind 4) copied from the exported bundle; build-kit runs that export into `.design-sync/.cache/kit-export` (about 20 s, `EXPO_OFFLINE=1`). Nothing in apps/ is edited.
- build-kit esbuild plugins mirror Uniwind's Metro web resolver: `react-native` goes to `uniwind/dist/module/components/web` (RNW wrappers with className), RNW `exports/<X>/index` and `createOrderedCSSStyleSheet` swap to the Uniwind wrappers (needed so RNW rules sit in `@layer rnw` below the Tailwind layers; without it every component renders unstyled). Resolve extensions prefer `.web.*`. `react-native-worklets/plugin` runs through babel on app source files that use reanimated or gesture-handler (otherwise `useAnimatedStyle` throws). The converter's own `reactShim` maps react to `window.React`.
- Not applied: the React Compiler (`react/compiler-runtime` has no shim). Behaviour is the same, only memoisation differs.
- Patches applied at bundle time (text replace in build-kit): uniwind `getWebStyles.js` appends its probe node to `document.body ?? document.documentElement` (the bundle can load in `<head>`); `expo/src/async-require/setup.ts` is stubbed (it opens Metro HMR websockets).
- Harness code lives in `.design-sync/kit-extras.tsx`: `DsRoot` (config.provider; startTheme + applyTheme from the app, Gesture/SafeArea/Query/Head.Provider/NavigationContainer with a one-screen navigator), `Stage` (themed box via the app's `ThemeScope`, optional width/height), `GlobalTheme` (switches the whole page theme; used by overlay Light cells because Modals portal outside `ThemeScope`), `ThemeScope`, and the helpers `notify`, `confirm`, `useBoardEditor` for previews. `Stage`, `GlobalTheme`, `ThemeScope`, `DsRoot` are excluded from the component list via `componentSrcMap: null`. `.design-sync/board-demo.tsx` and `transcript-demo.ts` hold preview fixture data; previews import them relatively.
- Dark and light: every preview exports a dark cell and a `LightTheme`/`Light` cell. Overlay components are `cardMode: single` (primaryStory `Dark`, viewport 800x520 or 800x560) because Modals fill the viewport; the Light cell is still captured and graded through `?story=`.
- Groups come from stub docs `.design-sync/docs/<Name>.md` (frontmatter `category` only, bound by `docsDir`). Components under `charts/`, `edit/`, `widget-board/`, `transcript-feed/` keep their directory group (the category only applies to the flat `general` group).
- `.d.ts` limits: converter turns any type longer than 240 chars into `unknown`, so `icon`, `name`, `colour` props show `unknown`; the values are published in `guidelines/docs/icons-and-colours.md` (generated by build-kit from `icon-glyphs.ts` and `tokens.ts`). `Gauge` props are overridden through `dtsPropsFor` because a non-exported `GaugeProps` in `virtual-list-header.tsx` collides by name. Other components whose props interface is not exported can hit the same collision; check a new component's `.d.ts` against its source.
- Playwright: the cached chromium build is 1234, which pins `playwright@1.62.1`; it is installed inside `.ds-sync/` only.

## Excluded components (componentSrcMap null)

Internal pieces with no standalone render: Axes, Extremes, MarkerLabel, MarkerLine (chart internals needing a model), DrawnStroke (needs a reanimated shared value), Frame (SVG path helper for brand glyphs), KeyboardViewport (keyboard-avoidance wrapper), LinkIntentProvider (context provider), ListTop and SectionHeader and RowScope (VirtualList internals), EditCanvas and EditableWidget and ResizeHandle (widget-board edit internals that need drag state and a PanGesture; shown through `WidgetBoard` Editing). Non-component exports (contexts, stores, hooks, gesture and keyboard utilities, ALL_CAPS constants) were never included: `ScreenContext`, `HeaderSlotContext`, `OverlayShown`, `HeaderSearchProvider`, `HeaderStatusProvider`, `ToastClock`, `RowVisibility` are listed in `.design-sync/kit-exclude.json`; the rest never match the PascalCase component rule.

## Known render warns

- None open after the last validate. `GRID_OVERFLOW` was resolved with `cardMode: column` on every flagged component.

## Product findings (no product change made)

- `Tooltip` sets `className="text-bg"` on a `Text` that also gets `text-on-surface`; `cn()` does not dedupe. Native Uniwind lets the later class win, web CSS order does not, so on web the tooltip text is invisible. The Tooltip preview injects `.text-bg{color:var(--color-bg) !important}` to show the native result.
- `DecisionFrame`'s `unavailable` prop is `string | null` in source but the emitted `.d.ts` says `string`.
- On web `PrimaryAction` and a header primary action both render as a header `Button` (`pointer` idiom), so a `Screen` with both shows two buttons.

## Re-sync risks

- Depends on `expo export` working offline and on Uniwind internals (`dist/module/components/web/*`, `createOrderedCSSStyleSheet`, `getWebStyles.js` text, `expo/src/async-require/setup.ts`). An Expo or Uniwind upgrade can break the text patches or the resolver mirror; symptom is unstyled cards (check `@layer rnw`) or console errors about `document.body` or websockets.
- Previews depend on product internals through harness data: `board-demo.tsx` (WidgetDefinition and BoardLayout shapes, `useBoardEditor`), `transcript-demo.ts` (TranscriptHit shape), HUB_FINGERPRINT in `HomeIdentity` (64 hex), `notify` and `confirm` store behaviour.
- `kit-extras.tsx` imports `startTheme`, `applyTheme`, `ThemeScope` and `CLIENT_PREFS.appearance.defaultValue`; renames in `apps/app/src/design` break `DsRoot`.
- New components appear automatically (build-kit scans PascalCase function exports) and ship on the floor card until a preview is authored; a name collision between two files keeps the first alphabetically.
- Overlay Light cells depend on `GlobalTheme`; if a Modal-based component is added, use `GlobalTheme` and `cardMode: single`.
- Partially verified: `CodeScanner` shows the camera-permission screen only (no camera in headless), `SwipeRow` and `ReorderableList` show the resting state, `ActionDetails` and `SchemaSettingsSheet` show their collapsed trigger, charts are drawn from synthetic data, touch idiom layouts (BottomSheet via `Sheet`, bottom-sheet menus) were not captured except `BottomSheet` itself.
- The build assumes Node 26, esbuild 0.28.2, ts-morph, playwright 1.62.1 under `.ds-sync/`.
